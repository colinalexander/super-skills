# Showcase: prepare and execute a launch

## Scenario

Launch a multi-client package for RelayDesk using the evidence in the focused marketing example. Produce a landing-page direction and, after explicit approval, share the approved launch brief with one named collaborator and send a notification.

## Skill composition

1. **`marketing-and-growth` owns the commercial decision:** target segment, positioning, package hypothesis, proof, conversion event, guardrails, and falsification criteria.
2. **`interface-design` owns presentation and interaction:** landing-page hierarchy, visual direction, responsive behavior, accessibility, and state coverage without inventing proof.
3. **`connected-service-automation` owns the external mutation:** resolve account, file, recipient, permission, and draft-versus-send state; execute the smallest authorized action and verify it.

Strategy does not authorize arbitrary file editing or sending. Visual polish does not create commercial evidence. Tool availability does not grant authority over a reachable collaborator.

## Deliverables

- Evidence-labelled positioning and package brief
- Responsive landing-page artifact with one primary action
- Approval record for the final brief
- Least-privilege share plan and verified notification receipt
- Measurement plan with conversion and trust guardrails

## Acceptance

The result must not invent prices or customer proof, let visual design obscure uncertainty, create a public link, select an ambiguous recipient, or send before the user's authorization is clear.

This is a showcase specification, not a completed comparative run.
