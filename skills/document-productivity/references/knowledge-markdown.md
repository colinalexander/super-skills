# Knowledge Markdown

## Write durable notes

Give each note a clear subject and purpose. Use concise properties only when they support search, views, or automation. Link concepts with stable names and include enough local context that a future reader can understand why the link matters.

## Preserve vault conventions

Inspect existing folder, naming, property, tag, link, callout, and attachment practices. Prefer the vault's established schema over introducing a parallel ontology. Update backlinks or indexes when renaming a shared concept.

## Use structure intentionally

Headings provide hierarchy; lists represent peers or steps; tasks represent actionable commitments; callouts emphasize a specific semantic role; embeds reuse a maintained source. Do not use specialized syntax merely for decoration.

## Validate portability

Check links, embeds, frontmatter, and fenced content. When the note must also work outside its native app, identify syntax that will degrade and choose a compatible representation or document the dependency.
