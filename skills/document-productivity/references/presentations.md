# Presentations

## Design the argument

Define the audience decision or takeaway, then create a narrative spine. Each slide should advance one claim, question, or transition. Use titles that state the point rather than merely naming the topic.

## Build native, editable slides

Use masters, layouts, theme colors, text boxes, shapes, charts, tables, and speaker notes appropriately. Preserve the supplied template. Keep repeated geometry aligned and avoid manually approximating charts with disconnected shapes when editable data is expected.

Before using a large template, inventory its masters and representative layouts, then map each narrative need to a verified layout. Treat slide indices as unstable implementation details and check them against the actual file before generation.

## Control density

Choose evidence that supports the slide's claim. Break complex sequences across slides or use progressive disclosure when presenting live. Ensure body text, labels, and footnotes remain readable at normal viewing size.

## Verify the deck

Render all slides and scan montage and full-size views. Check overflow, line breaks, font substitution, object collisions, image quality, contrast, chart labels, slide numbers, notes, and transitions. Confirm that the final deck opens in the target environment.
