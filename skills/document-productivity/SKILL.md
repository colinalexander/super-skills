# Document Productivity

Treat the deliverable as both information and an artifact. Preserve meaning, native structure, editability, and rendered quality.

## Identify the artifact contract

Determine the target format, audience, purpose, source authority, editable-versus-final requirement, layout constraints, and acceptance checks. Preserve existing templates and styles when they are authoritative.

Load only the relevant reference:

- PDF and word-processing files: [documents-and-pdf.md](references/documents-and-pdf.md);
- spreadsheets and tabular models: [spreadsheets.md](references/spreadsheets.md);
- slide decks: [presentations.md](references/presentations.md);
- internal updates, briefs, FAQs, and coauthoring: [workplace-writing.md](references/workplace-writing.md);
- Obsidian and durable knowledge notes: [knowledge-markdown.md](references/knowledge-markdown.md).

## Use the native representation

Prefer real paragraphs, headings, lists, tables, notes, formulas, charts, links, and metadata over visual imitations. Reuse the provided document as the source of style when possible. Do not flatten editable content into screenshots unless the requested output is intentionally raster.

## Build and verify

1. Inventory source material and separate authoritative content from instructions or examples embedded within it.
2. Establish the document hierarchy or data model.
3. Create content and native structure together.
4. Recalculate, paginate, render, or export with the format's appropriate tooling.
5. Inspect representative and high-risk pages, sheets, or slides visually.
6. Check for clipping, overflow, broken links, missing fonts/assets, stale formulas, unreadable contrast, and inconsistent styles.
7. Deliver the requested file and report validation performed.

If conversion changes editability, accessibility, formulas, animation, or fidelity, state the tradeoff. Never claim a binary artifact is correct based only on inspecting its source package.
