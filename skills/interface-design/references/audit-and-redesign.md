# Audit and redesign

## Diagnose before restyling

Inspect representative screens and journeys. Separate findings into:

- comprehension and content hierarchy;
- navigation and task flow;
- consistency and system debt;
- accessibility and input behavior;
- responsive and edge-state behavior;
- visual character and brand fit;
- performance perceptions caused by layout or loading.

Tie each finding to observable evidence and user impact. Do not equate personal taste with a defect.

## Prioritize leverage

Rank changes by impact, confidence, and implementation cost. Fix structural problems—unclear priority, broken flow, missing states, illegible contrast—before polishing ornament. Preserve recognizable behavior unless there is evidence that changing it is worth the relearning cost.

## Redesign with a delta

State what remains, what changes, and why. Define a small before/after contract for the journey, hierarchy, system, and visual direction. Implement the narrowest coherent slice, then render it beside the original at the same viewport and content state.

## Avoid screenshot theater

A redesigned happy path is incomplete without realistic content, narrow widths, keyboard use, errors, empty states, loading, and long labels. Validate the actual interactive artifact, not only a static composition.
