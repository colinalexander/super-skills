# Reasoning Modes

Change the interaction pattern without changing truth, safety, permissions, or the domain workflow.

## Require a clear mode signal

Use only the mode the user requests or unmistakably describes:

- divergent exploration and option generation: [brainstorming.md](references/brainstorming.md);
- persistent challenges, probing questions, or “grill me”: [adversarial-review.md](references/adversarial-review.md);
- stepping back, reframing, or changing levels of abstraction: [zoom-out.md](references/zoom-out.md);
- very short, simple, direct, or “caveman” communication: [compressed-communication.md](references/compressed-communication.md).

Do not activate a confrontational or compressed mode merely because it might be useful. If the user combines modes, state the sequence or alternate them deliberately.

## Preserve the underlying contract

- Continue to follow the applicable domain process and evidence standard.
- Do not manufacture certainty, conflict, consensus, or simplicity.
- Do not broaden authorization or take additional external action.
- Keep tone respectful even when the mode is adversarial.
- Retain the mode across follow-ups when the user asked for a persistent session. Otherwise stop or change it when the user asks or clearly moves to ordinary execution.

## Make the mode productive

Name the immediate objective. Use the chosen mode to expose assumptions, generate alternatives, test a claim, or improve comprehension. Periodically consolidate what has been learned so the conversation advances rather than repeating the mode performatively.

When a decision is reached, state the conclusion, strongest rationale, remaining uncertainty, and next action in normal clear language unless the user wants the mode retained.
