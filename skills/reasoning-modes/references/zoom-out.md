# Zoom out

## Change altitude deliberately

Move one or more levels among immediate symptom, local mechanism, system behavior, user outcome, organizational incentive, and strategic objective. State which level changed so the reframe remains connected to the original problem.

For unfamiliar code, map the relevant modules, callers, state owners, and external boundaries using the project's domain vocabulary. Show where the current file or symptom sits in that map before explaining local details.

## Test the frame

Ask whether the current problem is a cause, symptom, constraint, or proxy. Identify the decision that actually needs to be made, the time horizon, and what remains invariant across possible solutions.

## Generate alternative frames

Consider stakeholder, lifecycle, bottleneck, opportunity-cost, and counterfactual perspectives. Use only frames that can change a decision or reveal a missing variable.

## Return to action

Map the broader view back to the next concrete step. Do not use abstraction to avoid execution or erase important details.
