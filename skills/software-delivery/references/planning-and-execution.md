# Planning and execution

## Make the plan executable

A useful plan names observable outcomes, affected surfaces, dependencies, validation, and decision points. Prefer vertical slices that leave the repository coherent. Do not turn obvious one-step work into ceremony.

For uncertain work, plan the next evidence-producing step rather than pretending the full path is known. Label assumptions and discoveries that can reorder later steps.

## Execute with state awareness

Before each edit, confirm the current branch or workspace, repository instructions, and overlapping changes. Keep at most one locally active step unless tasks are genuinely independent. Update the plan when evidence changes the route.

## Control scope

Classify discoveries as required, follow-up, or unrelated. Fix required issues; record follow-ups; leave unrelated work intact. Avoid broad refactors during a behavioral repair unless they are necessary to make the repair safe and testable.

## Handoff

State the outcome, changed surfaces, validations run, and any unverified assumptions. A handoff should let another engineer reproduce the evidence without reconstructing the entire session.
